# Chembarathi Social Content Workflow Orchestrator

## Purpose

Coordinate social content work for Chembarathi Wayanad from the initial brief through final delivery. Use this file as the main workflow and follow the linked project files for detailed rules.

## Project references

- Project goal: `purpose.md`
- Visual requirements: `design_specs.md`
- Caption rules: `caption_guidelines.md`
- Image library and catalog: `assets/README.md` and `assets/image_library.md`

## Pre-work check

Before starting any task, read this orchestrator and all project guidance files relevant to the request. Inspect the relevant existing files and assets before making assumptions or drafting content. For social content, check `purpose.md`, `design_specs.md`, `caption_guidelines.md`, `assets/README.md`, and `assets/image_library.md`, plus any post files relevant to the request. Follow the most specific project guidance and verify details against the available source material.

## Workflow

### 1. Understand the request

Capture the platform, audience, post objective, relevant keyword, image or experience, requested format, and desired reader action. Check project materials for confirmed facts and contact details. Mark unknown details `[confirm detail]`; do not invent them.

Before creating a post from a new idea, first share its context with the user: the proposed angle, intended audience and objective, available verified images or details, and anything that remains uncertain. Offer a small set of clear creative options and wait for the user's direction before making post assets.

If the user chooses a carousel, request one image at a time in slide order. With each request, state the slide number, intended image context, and exact slide text. Confirm each received image and then request the next one. After all images arrive, add the originals to the image library according to `assets/README.md`, then prepare the slides.

### 2. Add supplied images to the library

For every supplied source image:

1. Copy the original into `assets/` without cropping, resizing, retouching, or otherwise changing its image content. Leave the source file untouched.
2. Give the library copy a clear, lowercase, underscore-separated filename based on visible content or supplied context. Do not guess details.
3. Add one entry to `assets/image_library.md` with the library filename, original filename, exact source path, description, visible subject details, and possible use. Note people, apparent gender presentation, broad age range when clear, animals, and whether the image is a photograph, illustration, or animation. Mark uncertain details as unknown; do not guess.
4. Keep a record for every supplied image. Do not select or discard images during library intake.

### 3. Plan the post

Choose one angle that fits the brief, such as nature, accommodation, romance, family, dining, guest experience, location, or booking. Confirm the image supports the planned message. Keep all new images in the library, whether or not they are used for this post.

### 4. Create the content

- Write the caption using `caption_guidelines.md`.
- In each post folder, keep the final caption as root-level `caption.md` with caption text only, no title or heading, alongside a `slides/` folder for visual assets.
- Create final visual assets using `design_specs.md` when requested. Render text and design directly into finished slide images in `slides/`. Deliver only finished slide images; do not save separate overlay or base files.
- If a crop or other image adjustment is needed for a post, make it in a separate post-specific working file. Never alter the original or library copy.

### 5. Review and deliver

Before delivery, check that:

- Claims match supplied or verified project information.
- The caption has one clear angle, a specific opening, and one relevant call to action.
- Booking details match the current verified project source; confirm them again before publishing.
- The tone is calm, warm, nature-led, and clear.
- Hashtags are relevant and accurate.
- Original and library images remain unchanged and uncropped.
- Any post-specific crops and design elements are separate from the library images.
- All requested files are present and named clearly.
- Inspect every finished slide yourself at normal viewing size for correct orientation, clear text, contrast, and line spacing; fix issues before delivery without waiting for the user to point them out.

If required information is missing, leave a clear placeholder and identify what needs confirmation before publication.
